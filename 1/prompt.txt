## (a) Large segments: new finding
Every size below got HTTP 200 from Sentry's relay. Each recording was one segment: Meta, then FullSnapshot, then one custom event padded with random data so it barely compresses.

| Compressed size | Stored? | Download |
|---|---|---|
| 0.50 MiB | yes | 200, identical |
| 0.90 MiB | yes | 200, identical |
| 0.93 MiB | yes | 200, identical |
| 0.97 MiB (1,017,104 B) | yes | 200, identical, 1.29 MiB in 187 ms |
| 1.2 MiB (1,258,338 B) | **no** (404 after 120 s) | |
| 1.5, 3, 5, 8, 9.9 MiB | **no** (404 after 120 s) | |
| 10.5 MiB | rejected with 413 | |

- **Silent loss:** the lost ones get no "invalid" outcome in Sentry's usage stats, so the browser can't tell they were dropped.
- **Likely cause:** the cutoff between 0.97 and 1.2 MiB matches Kafka's default 1 MB message limit, somewhere between relay and the replay consumer. The relay's own 10 MiB limit (the 413) only applies above that.
- **Decision needed:** either raise the Kafka message limits on dev (and later prod) for the replay recordings topic and relay's producer, or have package 6 cap segments at about 900 KiB compressed. A smaller cap only means more envelopes per report.
- **Tests:** F2 and F7 must download from Sentry, not trust the 2xx, or this failure passes unnoticed.

## How to run trace mode
1. Build with `SENTRY_BUILD_PROFILE=full` and any DSN set. The DSN is what turns on component annotation; I used a dummy one.
2. Run `BUG_REPORT_TRACE=1 BASE_URL=… npx playwright test --project=chromium &lt;specs&gt;`.
3. Optional switches:

## API as built
- `uploadReplay(buffer, ctx, opts?)` returns `{ok:true, replayId, segments, dropped?}` or `{ok:false, reason:"rate_limited"|"failed", replayId}`.
- `createReplayUpload(buffer)` is the adapter package 5 calls.
- **Segments:** one per checkout. A checkout over the cap is split at event boundaries, and segment 0 starts with Meta + FullSnapshot.
- **One event over the cap:** the checkout is cut just before it (the whole checkout goes if that event is the FullSnapshot), and the feedback gets `replay_truncated`. I didn't truncate the event instead, because a half-serialized node tree breaks every later event in that checkout.
- **Replay event:** `prepareEvent` runs, then only the replay fields, the five tags, `user: {id, ip_address: null}` and the user agent are kept. Scope breadcrumbs, extra and contexts are dropped because they were never redacted.
- **Retries:** 1 s then 2 s, 3 tries in total, for 5xx, network errors and a missing status code. 413 and other 4xx are permanent. 429 stops the report, and later attempts are refused while the limit lasts.

## Deviation from the brief: separate transport
Segments go out through `Sentry.makeFetchTransport` with the client's own tunnel URL, headers and options, but with `keepalive` off, instead of through `client.getTransport()`.

The reason is a bug F6 hit. The SDK marks bodies up to 60 KB as keepalive requests, and Chromium holds them against a 64 KiB budget until the response body is read, which the SDK never does. So small back-to-back sends, or a retry right after a failure, fail with "Failed to fetch" before reaching the network. The feedback that follows fails the same way, even with no interception. I reproduced this with plain `fetch` (script: `scratchpad/pkg6/keepalive.mjs`). The one cost is that rate limits are tracked in the upload module, not shared with the client's transport.

### Decisions
- **Unclassified values are tainted, not skipped.** Every string of 3+ characters under an unclassified key, and every string in an `/api/*` body, is tainted as `free_text`. UUIDs, ISO timestamps and numbers are excluded. In development a console warning names the key (never the value), once per key. A new column therefore over-redacts until someone classifies it, rather than leaking.
- **Enum rule for Json blobs.** The select parser now marks values found inside a Json or array column, or under a covering RPC path. For `free_text` values marked this way, the ingest skips single lower-case words (letters joined by `_` or `-`, at most 16 characters) plus UUIDs, timestamps and numbers. ## What I built
- **Redaction walker, in a Web Worker** (`lib/bugReport/redaction/`):
  - It keeps a node-id → text map and replays it forward through FullSnapshots and mutations (removes, adds placed in order, texts, attributes).
  - It rebuilds text per block element with offsets and maps hits back to the node that holds each piece, even when that node came from an earlier event. So `&lt;b&gt;Jane&lt;/b&gt; Doe` and a name added 30 s later both match.
  - Block text is matched two ways: joined as recorded (keeps a word split across elements whole) and with a space at inline element boundaries (adjacent links don't run together, which fixes the "Email the studentProfile link" issue). The spaced version is what the review list shows.
  - It covers every attribute value (not only title/alt/aria-label/placeholder/href/value), input events, console/click/fetch breadcrumbs, Meta `href`, the buffer's `urls`, the `&lt;title&gt;`, and CSS. Class names and CSS match on word boundaries only, so a short name doesn't break styling.
  - URLs are percent-decoded before matching, with a map back to the encoded bytes, and detectors treat URL delimiters as spaces. Without that, the backstop's email regex swallowed whole URLs.
  - Masking is same-length `*` and keeps whitespace, like rrweb; in URLs every character of a hit is masked.
  - The worker starts on the first `redactBuffer` call via `new Worker(new URL("./worker.ts", import.meta.url))`. The CSP needed no change: `utils/csp.ts` already allows `worker-src 'self' blob:`. The D8 test checks that the worker chunk loads with zero CSP violation reports.
- **API as built (matches CONTRACTS.md):**
  - `redactBuffer(buffer, {taintPatterns, extraRedactions?, keepLastMs?})` returns `{buffer, remaining, stats}`; I added `disposeRedactionWorker()`.
  - `extraRedactions` treats `*` as a wildcard, so a string copied from `remaining` (already masked) still finds the original text.
  - `remaining` has one entry per run of inline text, grouped by kind with counts.
  - `taintSnapshot()`: ingest's merge replaced my version; it now only flattens the set, which stores normalized patterns.
  - Package 4's model plugs in through `setModelDetector()` in `redact.ts`.
- **`&lt;ReportBlock&gt;`** (`components/bugReport/ReportBlock.tsx`): with a single element child it adds `data-report-block` to that element, so there is no extra DOM and rrweb measures a real box. Otherwise it renders a `span` (or `div` with `as="div"`). I didn't use `display: contents` because rrweb would record a 0×0 placeholder. I applied it across about 70 files, including all the pii-sinks components and the survey answers. Avatars were already blocked by the recorder's selector.

## How it works
Run with `BUG_REPORT_TRACE=1 BUG_REPORT_TRACE_UPLOAD=1` (add `BUG_REPORT_TRACE_STRICT=1` for strict mode).
- **Course flag:** turned on through the service role before the first request to each `/course/&lt;id&gt;`, so the page's own flag lookup already sees it.
- **Route policy:** every course page goes through the localStorage override. Pages already in `ROUTE_POLICY` keep their level. `manage/*`, `grade/*`, discussion, office hours, polls and regrade requests get `structure`, and every other course page gets `full`.
- **When it scans:** before each `goto`/`reload`, before `page.close` and `context.close`, at the end of each test, and at worker teardown. Each scan uses the real freeze → redaction worker path, plus the feedback payload.
- **Report:** `report.json` gets an `uploads` section: counts, hits by kind, column, route and place in the upload, course pages with no recorder by route, and pages that couldn't be scanned with the reason. How to run it is also written up in `lib/bugReport/PRIVACY_REVIEW.md`.

- **Why tests pass:** E1–E4 and K3 read the iframe's text and node count, never what is on screen.
