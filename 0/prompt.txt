## SDK checks (@sentry/core 10.3.0)
- **Binary items:** `serializeEnvelope` appends a `Uint8Array` payload unchanged. A round trip of random bytes and of a real recording containing `\n` bytes came back byte-identical (`check-serialize.mjs`).
- **Transport gotchas:**
  - If an earlier response rate-limited replays, `send()` quietly drops the items and returns `{}` with no `statusCode`, so package 6 must treat a missing status as failure.
  - For bodies of 60 KB or less the browser transport sets `keepalive`. That only happens at submit, but B3's "no keepalive" assertion needs to allow it there.
- **`sendFeedback(…, {includeReplay:false})`:** `includeReplay` is only read by `replayIntegration`, which we don't install, so replay code is never touched. Two side effects:
  - It calls `getCurrentScope().setTags(params.tags)`, which leaves `class_id`, `contact_ok` and the rest on every later error. Call it inside `withScope`, or set the tags in the hook instead.
  - It defaults `url` to `location.href`, the concrete path with ids, which becomes the `url` tag and `contexts.feedback.url`. Pass `url` explicitly if D17 wants only the route pattern.
- **`beforeSendFeedback`:**
  - It's a client hook (`client.on(...)`), not an init option.
  - It runs synchronously and gets the raw feedback event. It can change `contexts.feedback.replay_id`, `tags`, `user` and `contexts` in place.
  - It can't drop the event, async work in it isn't awaited, and the scope's data is merged in afterwards.
  - `beforeSend` does not run for feedback at all.
